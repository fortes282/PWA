# Kilo Code konfigurace pro Přístav Radosti

## Přehled

Cíl: Kilo automaticky ví o projektu bez zbytečného kontextu navíc, a po každé implementaci
samo spouští kompletní ověření (typy + testy + lint) a opravuje případné chyby.
Žádné ruční příkazy — workflow je: navrhni → implementuj → otestuj vše → oprav.

---

## Soubory k vytvoření

### 1. `AGENTS.md` (kořen projektu)

Nejdůležitější soubor. Kilo ho čte automaticky při každé sessii — trvalý kontext bez opakování.

**Sekce A — Popis projektu:**
- Neurorehabilitační centrum "Přístav Radosti"
- pnpm monorepo: `apps/api` (Fastify 5 + Drizzle ORM), `apps/web` (Next.js 15 App Router), `packages/shared` (Zod schemas)
- Databáze: SQLite (dev/`:memory:` testy) ↔ PostgreSQL (produkce) — přepínáno přes `DATABASE_URL`
- Rolový systém: `CLIENT | RECEPTION | EMPLOYEE | ADMIN`

**Sekce B — Coding conventions:**
- UI texty vždy **česky**
- Nová API route: soubor v `apps/api/src/routes/*.ts` → import + `fastify.register()` v `server.ts`
- Nová frontend stránka: `apps/web/src/app/{role}/{name}/page.tsx` s `RouteGuard` + `Layout`
- Sdílené Zod schémata patří do `packages/shared/src/schemas/`
- Design: Tailwind třídy z `tailwind.config.ts`, **nikdy inline hex** (primary `#242B61`, secondary `#E86A24`)
- Animace: Framer Motion **vždy** s `useReducedMotion()` respektem
- Data fetching: SWR + `api.get<TypovanýInterface>()` — **nikdy `api.get<any>()`**
- Password hashing: **výhradně** `hashPassword()` / `verifyPassword()` z `utils/hash.ts` (scrypt) — nikdy raw SHA-256
- Zdravotní data: AES-256-GCM přes `utils/crypto.ts`
- Auth context v route handlerech: `request.auth!` = `{ id, email, name, role }`
- API route pattern: Zod validace → RBAC check → DB operace → `logAudit()` → response
- Dual-DB: vždy abstraktní Drizzle `db` klient, **nikdy** `rawSqlite` mimo testy

**Sekce C — Povinný post-implementační workflow:**

Po **každé** změně kódu, bez výjimky, spusť v tomto pořadí:
```
1. pnpm --filter @pristav/shared tsc --noEmit
2. pnpm --filter @pristav/api   tsc --noEmit
3. pnpm --filter @pristav/web   tsc --noEmit
4. pnpm --filter @pristav/api   test
5. pnpm --filter @pristav/web   test
6. pnpm lint
```
Pokud jakýkoliv krok selže — **oprav chyby a zopakuj celou sekvenci**.
Úkol je dokončen teprve po zeleném průchodu všech 6 kroků.
Výjimka: pokud jde o čistě frontendovou změnu bez dotyku API, kroky 1+4 lze přeskočit,
a při čistě backendové změně lze přeskočit kroky 3+5.

**Sekce D — Rychlá reference:**
- `pnpm dev` — spustí api + web paralelně
- `pnpm build` — build všech packages
- `apps/api/src/db/schema.ts` — Drizzle schéma (48+ tabulek)
- `apps/api/src/server.ts` — registrace všech routes
- `apps/web/src/lib/api.ts` — centrální fetch client
- `apps/web/src/components/` — sdílené UI komponenty
- `packages/shared/src/schemas/` — Zod schémata sdílená mezi API a web

### 2. `kilo.json` (kořen projektu)

```json
{
  "instructions": ["AGENTS.md"],
  "snapshot": true
}
```

- `instructions` — AGENTS.md se načítá jako součást kontextu každé sessie
- `snapshot: true` — git snapshot před každou větší změnou (možnost rollbacku)

### 3. `.kilo/agent/pristav-dev.md`

**Jeden hlavní full-stack agent** místo dvou oddělených. Uživatel ho nemusí ručně přepínat — Kilo ho používá automaticky pro úkoly na tomto projektu.

**Frontmatter:**
```yaml
---
description: Hlavní vývojář pro Přístav Radosti — full-stack Fastify + Next.js, vždy testuje vše
mode: primary
color: "#242B61"
steps: 40
---
```

**Systémový prompt (klíčové body):**
- Zná celou architekturu monorepa (Fastify 5 / Drizzle / Next.js 15 / SWR / pnpm)
- Pracuje vždy v cyklu: **analyzuj → navrhni přístup → implementuj → spusť kompletní ověření**
- Při implementaci API + frontend změn dělá obojí najednou (nečeká na potvrzení mezi)
- Po implementaci vždy spustí sekvenci z AGENTS.md Sekce C a opraví vše červené
- Při změně Drizzle schématu automaticky:
  - upraví `schema.ts`
  - spustí `pnpm --filter @pristav/api db:generate`
  - zkontroluje dopad na routes a Zod schémata v shared
  - zkontroluje `seed.ts` pro nové NOT NULL sloupce
- Rozumí specifickým vzorům: dual-DB, scrypt hashing, AES-256-GCM health data, JWT + 2FA flow

3. `.kilo/agent/pristav-dev.md` — specializovaný agent s plnou znalostí projektu
